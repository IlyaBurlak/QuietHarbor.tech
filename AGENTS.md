# Wishlist (QuietHarbor.tech)

Веб-приложение: вишлисты, бронь подарков втайне от владельца, друзья, «Тайный Санта», админ-панель.
Полный план MVP, модель данных и задачи по эпикам: `docs/MVP-plan.md` — **источник истины**, читай нужный эпик перед задачей.

## Структура (npm workspaces)
- `client/` — React + TS + Vite, архитектура **FSD** (см. `client/AGENTS.md`)
- `server/` — Express + TS + Prisma, модульная архитектура (см. `server/AGENTS.md`)
- `shared/` — `@wishlist/shared`: Zod-схемы и типы, общие для клиента и сервера (импортируются как TS-исходники)
- `README.md` — витрина проекта; `client/README.md` и `server/README.md` — документация, заполняется по ходу
- `docs/` — `MVP-plan.md` (план), `DESIGN.md` (дизайн, UX, адаптив, анимации, футер)

## Команды (из корня)
- `npm run dev` — база в Docker + миграции + бэк (:3000) + фронт (:5173)
- `npm run dev:db` / `dev:down` / `dev:reset` — управление локальной базой
- `npm run db:migrate` (создать миграцию), `db:deploy`, `db:seed`, `db:studio`, `create-admin`
- `npm test`, `npm run lint`, `npm run typecheck`, `npm run build`
- Полный список команд и прод-стек: эпик 1 в `docs/MVP-plan.md` ; прод-стек: `compose.prod.yml` + `deploy/`, команды `npm run prod:*` (см. README)

## Правила проекта
- Все входящие данные валидируются на сервере через Zod; схемы живут в `shared/`.
- Права доступа проверяются только на бэке; скрытие кнопки на фронте — удобство.
- В БД хранится ключ файла (`fileKey`), не путь — для будущего переезда на S3.
- Единый формат ошибок API: `{ code, message, fields? }` (`shared/src/errors.ts`).
- Владелец вишлиста **никогда** не видит брони на свои товары — проверять в каждом эндпоинте.
- Секреты только в `.env` (в git не попадает); новые переменные добавлять в `.env.example` и в Zod-схему `server/src/config/env.ts`.
- UI: Ant Design, тёмная «стеклянная» тема в стиле Ohmywishes (токены — `client/src/app/providers/theme.ts`), иконки lucide-react, шрифт Onest; русская локаль; адаптив через Row/Col и медиазапросы.
- Язык интерфейса и сообщений об ошибках — русский. Код и идентификаторы — английский.
- Коммиты небольшие, по задачам из плана (номер задачи в сообщении, например «2.1: регистрация»).
- Любой UI делай по `docs/DESIGN.md`: mobile-first, доступность (WCAG AA), тёмное стекло без «светящихся» градиентов и чужих брендовых элементов, короткие анимации с учётом `prefers-reduced-motion`.
