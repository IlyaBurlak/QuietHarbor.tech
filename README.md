## О проекте

Wishlist решает простую проблему: люди не знают, что подарить, а подарки получаются одинаковыми или ненужными. В приложении:

1. вы заводите **вишлисты** («День рождения», «Новый год») и добавляете желания: название, цена, фото, ссылка на магазин;
2. **делитесь ссылкой** — друзьям не нужно регистрироваться, чтобы посмотреть список;
3. друзья **бронируют подарки втайне от вас**, и никто не дарит одно и то же дважды;
4. компании играют в **Тайного Санту** с честной жеребьёвкой на сервере.

### Главные принципы

- **Секретность.** Владелец вишлиста не видит брони на свои подарки — данных о них нет даже в ответах API. Организатор Санты не видит чужие пары.
- **Приватность.** Каждый вишлист: «только я», «по ссылке» или «для друзей». Права проверяются только на сервере.
- **Доступность и адаптив.** Интерфейс рассчитан на телефон, планшет и ноутбук, соответствует WCAG 2.2 AA и не навязывает анимации.
- **Минимум личных данных.** Вход по нику и паролю или через Telegram, Google, GitHub; почта и телефон не нужны.

## Возможности MVP

| Раздел        | Что входит                                                                                  |
| ------------- | ------------------------------------------------------------------------------------------- |
| Аккаунт       | регистрация и вход по нику, профиль, дата рождения с гибкой видимостью, аватар              |
| Вишлисты      | несколько списков, приватность, публичная ссылка с перевыпуском, сортировка и drag-and-drop |
| Товары        | ручной ввод, до 5 фото, похожие товары, приоритет                                           |
| Бронь         | бронь и «куплено» втайне от владельца, страница «Мои подарки»                               |
| Друзья        | поиск по нику, заявки, календарь дней рождения                                              |
| Тайный Санта  | группы, приглашения, исключения, жеребьёвка на сервере                                      |
| Администратор | статистика базы, сброс паролей по заявкам, блокировка аккаунтов, журнал действий            |

Статус задач по эпикам — в [плане MVP](docs/MVP-plan.md).

## Быстрый старт

Нужны Node.js ≥ 20 и Docker.

```bash
git clone <адрес-репозитория>
cd QuietHarbor.tech
cp .env.example .env     # значения для разработки уже подходят
npm install
npm run dev              # база в Docker + миграции + API :3000 + фронт :5173
```

Откройте <http://localhost:5173>. Дополнительно:

```bash
npm run db:seed          # тестовые пользователи alice / bob, пароль password123
npm run create-admin     # администратор из ADMIN_USERNAME / ADMIN_PASSWORD
npm run db:studio        # просмотр базы в браузере
```

## Админка

Откройте `/admin/login` (ссылок на неё в обычном интерфейсе нет) и войдите ником и паролем администратора. Администратора создаёт команда `npm run create-admin` (локально) или `npm run prod:create-admin` (в Docker); обычный регистрацией админом не стать. Сессия админки живёт 2 часа. В панели: статистика базы, заявки на сброс пароля, пользователи с блокировкой и журнал действий. Содержимое вишлистов, броней и пар Тайного Санты админу недоступно.

## Проверки перед релизом

`npm test` прогоняет интеграционные тесты, среди них: карта доступа (каждый маршрут API без входа отвечает 401, новый эндпоинт без защиты роняет тест), чужие данные (403/404), отсутствие хэшей и скрытых данных в ответах, CORS, cookie, загрузка файлов (подделка формата, SVG, «бомба распаковки», EXIF) и сквозные сценарии «желание → бронь» и «жеребьёвка Санты».

## Прод-стек (Docker)

Caddy (HTTPS, фронтенд, раздача фото) + бэкенд + PostgreSQL + разовый контейнер миграций. Конфиги: `compose.prod.yml`, `deploy/`.

```bash
cp .env.production.example .env.production   # заполнить секреты и домен
npm run prod:up                              # собрать и запустить (миграции применяются сами)
npm run prod:create-admin                    # создать администратора из ADMIN_* в .env.production
```

| Команда                                | Что делает                                                    |
| -------------------------------------- | ------------------------------------------------------------- |
| `npm run prod:build`                   | собрать образы                                                |
| `npm run prod:up` / `prod:down`        | запустить / остановить стек (тома с базой и фото сохраняются) |
| `npm run prod:migrate`                 | применить миграции вручную                                    |
| `npm run prod:logs`                    | логи                                                          |
| `npm run prod:create-admin`            | создать/обновить админа (пароль виден только этому контейнеру) |
| `npm run prod:reset-link -- WL-XXXXXX` | одноразовая ссылка сброса пароля по коду заявки               |

Для проверки на своём компьютере: `SITE_ADDRESS=http://localhost`, `HTTP_PORT=8080`, `CLIENT_URL=http://localhost:8080` в `.env.production`.

**Фото** при загрузке проверяются по содержимому (JPG, PNG, WebP до 5 МБ), пересобираются в WebP с длинной стороной до 1200 px (аватары 512×512) и очищаются от EXIF. Типичное фото занимает 20–100 КБ вместо нескольких МБ, поэтому диск почти не растёт.

**Фото пользователей** лежат в Docker-томе `uploads` (переживает пересборку и `prod:down`; `docker compose down -v` его удалит). Файлы отдаёт напрямую Caddy из этого тома с кешем на год, не нагружая Node. Том `caddy_data` хранит сертификаты, его тоже не удаляйте.
